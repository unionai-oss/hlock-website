The package manager for agent harnesses

Your agent setup,
made portable.

Your agent is more than a model. It's a harness version, MCP servers, skills, plugins, instruction files, and config you set up by hand on one machine. hlock pins all of it in a harness.lock you commit to git, and brings it back anywhere.

The fix

          
One file.
Every dependency.

          

            hlock pin reads the harness you already use and writes everything it depends on
            into harness.lock: versions, sources, digests. Hand-written skills and config
            are vendored next to it in .hlock/, so the pair is self-contained.
          

          
    
            
  • Harness version and install source
    • 
            
  • Models per role, and where each came from
    • 
            
  • MCP servers, normalized across config formats
    • 
            
  • Skills, plugins & instructions, each with a digest
    • 
            
  • Secrets as placeholders, never values
    •

Familiar by design

        
You already know how this works.

        
If you've used uv, cargo, or npm, you already know the shape of hlock.

        

          

            uv.lock · Cargo.lockharness.lock
            
Every dependency of your harness, pinned and hashed.

          

          

            pip freezehlock pin
            
Record the setup you already have. Re-pin as it grows.

            uv sync · npm cihlock sync

Safe to commit

          
Secrets stay out.
Always.

          

            pin never writes a secret. API keys, tokens, auth headers, and
            credential-looking values become HLOCK_SECRET_* placeholders.
            You supply the values when you sync, and a real secret is never replaced with a placeholder.
          

        

        

          

            
~/.claude.json


"github": {
  "command": "npx",
  "env": {
    "GITHUB_TOKEN": "ghp_8kQx2LmZ0vYt…""${HLOCK_SECRET_GITHUB_GITHUB_TOKEN}"
  }
}

          

          

            
              
            
            1 secret redacted · supplied as HLOCK_SECRET_* when syncing
          

        

      

    


    
    

      

        
Rehydrate anywhere

        
Same agent. Any machine.

        
hlock sync builds a plan: what's already satisfied, what it does for you, and the exact command for anything it can't.

        

          

            

              
            

            
A new laptop

            
Clone the repo, sync, set your secrets. Your config, skills, and plugins land where the harness expects them.

            
$ git clone …/my-app && cd my-app
$ hlock sync --install

          

          

            

              
            

            
An isolated env

            
Like a virtualenv for your harness. Materialize the lock into its own config root and leave yours untouched.

            
$ hlock sync --prefix .hlock/env
✓ in sync at .hlock/env/claude-code/config

          

          

            

              
            

            
A container

            
Write a Docker build context with the restored config baked into the image's home. Ship your agent to CI or a cluster.

            
$ hlock sync --docker
✓ wrote .hlock/docker/pi/Dockerfile

          

        

        

          tip
          
Some steps need a human, like installing an app or setting a secret. hlock sync --skill writes an Agent Skill from the plan, so any agent can finish the job for you.

        

      

    


    
    

      

        
Then make it better

        
A locked harness is a baseline.

        
Once your setup is reproducible, you can measure it. Every lock hlock resolves records its success rate, cost, and latency on your own tasks.


        

          

            

              hlock resolve
              like uv lock
            

            
Find the best stack for your tasks

            
Draft an eval pack from the sessions your agent already logged, list the models and harnesses to try in harness.toml, and lock the winner with its evidence.

            

              
            

          


          

            

              hlock tune
              like PGO
            

            
Tune what's inside

            
Go past model choice into prompts, hyperparameters, and fine-tuned small models, on your evals. Run locally, on a devbox, or lift trials to a Flyte cluster for GPUs.


$ hlock tune --backend cluster --depth ft

              like cross-compiling

Lock it in under a minute.

        

          
quickstart


$ pip install hlock
$ hlock pin                      # lock your current setup into harness.lock
$ git add harness.lock .hlock/   # version it (secrets are placeholders)
$ hlock check                    # see what changed since the pin
$ hlock sync                     # on another machine: rehydrate it
$ hlock launch                   # start a session on the locked setup
